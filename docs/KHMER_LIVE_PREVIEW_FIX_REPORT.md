# Docera — Khmer Live Editor Preview & WYSIWYG Fidelity Fix Report

**Report Date:** November 14, 2026

**Target Branch:** `feature/continuous-dev`  
**Components Affected:** `frontend/src/features/editor/PdfEditor.tsx`, `frontend/src/services/fontResolver.ts`, `frontend/src/features/pdf-viewer/pdf.ts`, `frontend/src/services/toolsApi.ts`, `frontend/src/styles/app.css`

## Executive Summary

Docera previously achieved pixel-accurate and structurally valid native PDF text replacement for complex-script Khmer typography in exported PDFs using HarfBuzz shaping, FreeType rasterization, PyMuPDF vector streams, and ToUnicode CMaps.

However, an editor WYSIWYG fidelity defect remained: while the exported PDF was visually correct, the on-canvas live editor preview staged replacements inside an HTML DOM overlay. This produced a noticeable mismatch where the preview exhibited unstyled or misaligned glyphs before export.

This issue has been resolved. Docera now features an **Authoritative In-Memory PDF Live Preview Engine** paired with a **Font Resolution & Preloading Service**. As the user edits text, Docera applies debounced backend vector replacements in-memory and renders them authoritatively through PDF.js on the editor canvas. The preview displayed in the browser is rendered by the exact same engine and font program that produces the final exported PDF, achieving 100% WYSIWYG fidelity.

---

## 1. Confirmed Root Cause Analysis

Thorough investigation of the editor preview path vs. the export pipeline identified four core discrepancies:

### A. Subset Prefix Mismatch in CSS Font Resolution
- **Symptom:** The editor properties panel detected `KhmerOSBattambang`, but the replacement text in the DOM overlay rendered in a fallback font (such as Windows `Leelawadee UI` or default `sans-serif`).
- **Root Cause:** In the original PDF content stream, fonts are subsetted according to ISO 32000-1 §9.6.4 with a random 6-uppercase-letter tag and plus sign (e.g., `BAAAAA+KhmerOSBattambang`). The frontend received this exact string. When applying `fontFamily: "BAAAAA+KhmerOSBattambang"` to the DOM overlay, browser CSS font matching failed because the `@font-face` rule only declared `KhmerOSBattambang`. The browser silently fell back to system defaults which lacked OpenType subscript and coeng shaping features.

### B. Typographical Baseline vs. CSS Box Model
- **Symptom:** Replacement text sat slightly higher or lower than the original line of text.
- **Root Cause:** In PDF vector graphics, text is positioned relative to an exact typographical baseline (`origin[1]`). In HTML DOM, an element with `line-height: normal` centers glyphs vertically within its content box. For complex scripts like Khmer with tall ascenders (e.g., `៊`, `៍`) and deep subscript consonants (e.g., `្ជ`, `្ធ`), CSS vertical centering shifts the baseline compared to the native PDF baseline coordinate.

### C. Opaque Redaction Box Limitations
- **Symptom:** In the DOM preview, original text was concealed using an opaque white rectangle (`#ffffff`). If the PDF had off-white paper, textured backgrounds, adjacent underlines, or gridlines, the white box clipped visual elements, revealing the preview overlay as an artificial patch.

### D. Async Font Loading Race Condition
- **Symptom:** Edits typed immediately after loading the editor occasionally rendered in fallback fonts until a page reload or re-render occurred.
- **Root Cause:** `@font-face` web fonts are loaded lazily by the browser upon first encounter in the DOM. Without explicit preloading through `document.fonts.load()`, measurement and rendering occurred before font glyphs were available.

## 2. Technical Architecture & Implementation

To solve the preview/export mismatch at the root without brittle CSS offsets or approximations, Docera introduced a dual-layer architecture:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                            Docera Editor Canvas                             │
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │ PageCanvas (PDF.js Canvas)                                            │  │
│  │ Renders authoritative in-memory PDF generated by backend              │  │
│  │ (HarfBuzz shaped, TrueType embedded, exact vector baselines)          │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
│                                    ▲                                        │
│                                    │ Live In-Memory PDF                     │
│  ┌─────────────────────────────────┴─────────────────────────────────────┐  │
│  │ Staged Edits Debounce Controller (200ms)                              │  │
│  │ toolsApi.nativeApplyEdits(docId, edits, { signal })                   │  │
│  │ ➔ loadPdfFromData(previewBytes) ➔ previewPdf                          │  │
│  └─────────────────────────────────▲─────────────────────────────────────┘  │
│                                    │ Edit Event                             │
│  ┌─────────────────────────────────┴─────────────────────────────────────┐  │
│  │ DOM Interactive Hitbox Layer (.preview-synced)                        │  │
│  │ - Transparent background (shows true PDF canvas beneath)              │  │
│  │ - Replacement text opacity: 0 (interactive, accessible, invisible)   │  │
│  │ - Selection handles, resize borders, and click-to-edit preserved      │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1. Font Resolver & Eager Preloader (`frontend/src/services/fontResolver.ts`)
- **`cleanPdfFontName(rawName)`:** Strips 6-letter subset prefixes (`BAAAAA+`, `CDEFGH+`) and cleans font family identifiers.
- **`resolveEditorFontFamily(fontName)`:** Matches detected PDF fonts against bundled TrueType fonts with fallback precedence matching `backend/app/services/layout_engine.py`:
  1. `KhmerOSMuol` / `Muol`
  2. `Noto Serif Khmer`
  3. `Noto Sans Khmer`
  4. `KhmerOS` / `KhmerOSBattambang`
- **`ensureFontLoaded(fontFamily, weight)`:** Uses the standard `FontFace` API to load and inject font programs into `document.fonts`.
- **`preloadAllKhmerFonts()`:** Invoked eagerly upon editor initialization to ensure all Khmer font weights are pre-warmed in memory before user interaction.

### 2. In-Memory PDF Loading Task (`frontend/src/features/pdf-viewer/pdf.ts`)
- Implemented `loadPdfFromData(data: Uint8Array | ArrayBuffer)`:
  - Configures standard font URLs, cMap URLs, and WebAssembly decoders identical to the main document viewer.
  - Returns a managed `PDFDocumentLoadingTask` with memory cleanup hooks.

### 3. Request Abort Controller (`frontend/src/services/toolsApi.ts`)
- Added optional `signal?: AbortSignal` to `nativeApplyEdits` and `postToolForm`.
- When rapid typing occurs in the replacement text box, in-flight preview requests are safely aborted, eliminating race conditions and minimizing backend load.

### 4. Authoritative Preview & Seamless Canvas Swap (`frontend/src/features/editor/PdfEditor.tsx`)
- Maintained `previewPdf: PDFDocumentProxy | null` and `previewBytes: Uint8Array | null`.
- When staged edits are active, `<PageCanvas pdf={previewPdf || pdf} ... />` is fed the authoritative preview document.
- Both the main document viewport and the left-rail thumbnail stack display the live authoritative preview.
- **Interactive Overlay Synchronization:**
  - When authoritative preview is active, edited text spans receive the CSS class `.preview-synced`.
  - In `.preview-synced` mode, the DOM overlay background becomes `transparent` and `.existing-text-replacement` has `opacity: 0; pointer-events: none;`.
  - The user sees the true vector PDF rendered on the canvas with 100% fidelity.
  - The DOM element remains positioned as an interactive hitbox so the user can re-click, select, or modify text without disruption.
- **Header Status Badge:**
  - Displays `Authoritative PDF synced` when the preview matches staged edits.
  - Displays `Syncing preview...` while debounced background synthesis is active.
- **Zero-Latency Instant Export:**
  - When clicking "Export PDF", if `previewBytes` is already cached and up to date, Docera reuses the in-memory binary directly, triggering an instant download without a redundant roundtrip.
